# Нативный kit на Rust

Один бинарник управляет установкой, Linux VM, командами Docker, веб-агентом и автоостановкой. Установленному kit не нужны Python, Cargo или Rust. QEMU запускает Linux, а системные SSH и SCP связывают CLI с гостевой системой.

PHP-шлюз остаётся в `~/public_html/helios-container`. Университетский веб-сервер обеспечивает публичный HTTPS, локальный агент на Rust принимает запросы только через loopback. Интерфейс остаётся HTML/CSS/JS.

## Сборка и установка из исходников

Нужны FreeBSD 14 amd64, Rust, Cargo и системный C-компилятор:

```sh
sh native/build.sh
./native/target/release/helios-container-native install
. "$HOME/.profile"
```

Установщик поддерживает `--prefix PATH`, `--memory N`, `--cpus N`, `--disk N`, `--no-profile` и `--no-launchers`. Существующая VM и её настройки сохраняются при повторной установке.

`sh install.sh --source` собирает kit на helios. Если Cargo отсутствует, bootstrap временно установит компилятор в каталог сборки и удалит его после установки. Это не создаёт зависимость от компилятора у установленного kit.

Linux-бинарник нельзя устанавливать на helios. Собирать и проверять FreeBSD-бинарник нужно на совместимой FreeBSD. Библиотеки Cargo входят в бинарник, системные библиотеки FreeBSD остаются необходимыми.

## Существующая установка

Нативный kit использует прежние `config.json`, `web.json`, диск `vm/docker.qcow2`, SSH-ключ, пробросы и ключ панели. Неизвестные поля конфигурации сохраняются. Повторно создавать VM или переносить контейнеры вручную не требуется.

Для нестандартного каталога укажите `--base /полный/путь` перед командой. После установки проверьте:

```sh
helios-container version
helios-container status
docker ps
helios-container web info
```

Версия установки читается из `VERSION`, при его отсутствии отображается `dev`. Версия Rust runtime выводится отдельно.

## Готовые релизы

Публикация релизов ведётся отдельно от этой миграции. Нативный релиз должен содержать бинарник `helios-container-freebsd-amd64`, его контрольную сумму `helios-container-freebsd-amd64.sha256` и файл `VERSION`. Версия в `native/Cargo.toml` должна совпадать с тегом релиза, команда `--build-version` проверяет её независимо от файлов установки. PHP-шаблон и `.htaccess` включаются в бинарник. Старые архивы с Python-установщиком не являются нативными релизами.

До публикации совместимого нативного бинарника используйте сборку из исходников. Наличие исходников Rust в репозитории само по себе не означает, что готовый бинарник уже опубликован.

## Проверки и ограничения

`cargo test --locked` проверяет нативные компоненты. Дополнительная проверка `python3.11 tests/lifecycle.py target/release/helios-container-native` использует одноразовую fixture в системном временном каталоге. Python нужен только этому тестовому инструменту, он не входит в установленный kit.

Rust не заменяет QEMU и не добавляет аппаратное ускорение. CPU по-прежнему эмулируется через TCG, лимиты пользователя и квоты сервера сохраняются.

Шлюз поддерживает обычные HTTP-запросы. Данные панели обновляются через HTTPS polling. WebSocket, SSE и потоковые ответы через PHP-шлюз не поддерживаются. Остановленная VM не запускается от просмотра панели.
