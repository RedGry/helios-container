# Веб-панель и HTTPS

Веб-шлюз публикует HTTP API через `https://se.ifmo.ru/~USERNAME/`. Backend может работать в контейнере или обычным процессом на helios. SSH-туннель не нужен.

## Включение

Запустите приложение с опубликованным портом, затем включите шлюз:

```sh
helios-container web install
```

Хостингу нужен проход по домашнему каталогу и чтение с проходом по `public_html` и каталогу шлюза. Если прав недостаточно, установка сообщает путь, текущие права и команду исправления:

```sh
chmod 711 "$HOME"
chmod 755 "$HOME/public_html"
chmod 755 "$HOME/public_html/helios-container"
```

Выполняйте нужную команду только для существующего каталога. Установщик проверяет права и при повторной установке, сохраняет права существующих каталогов и создаёт новые с `755`. Ошибка проверки PHP включает URL и причину HTTP/сетевого сбоя; временный проверочный файл удаляется и при ошибке.

Откройте выданную **приватную ссылку управления**. Её можно получить повторно командой `helios-container web info`.

В разделе «Порты» укажите маршруты:

| Ввод | Backend | Путь после `index.php` |
| --- | --- | --- |
| `8080` | Порт VM | `/vm/8080/` |
| `8080, 8081` | Два порта VM | `/vm/8080/`, `/vm/8081/` |
| `host:3000` | Ваш процесс на helios | `/host/3000/` |
| Пустое поле | Закрыть все маршруты | — |

Сохранение заменяет весь список; можно опубликовать до 8 портов. Для маршрутов VM она должна быть запущена. Пробросы создаются автоматически.

Процесс `host:PORT` должен принадлежать вашему пользователю и слушать IPv4. Предпочтительный адрес — `127.0.0.1`.

## Панель

Панель показывает контейнеры, проекты Compose, образы, volumes, порты и ресурсы VM. Доступны запуск, остановка, перезапуск и просмотр логов. Можно выбрать тёмную, светлую или системную тему.

- Действия с проектом применяются к существующим контейнерам. Изменения Compose-файла применяйте через CLI.
- Перед удалением остановите контейнер. Его образ и volumes сохраняются.
- Удаление volume уничтожает данные. Используемые образы и volumes удалить нельзя.
- Удаление группы Compose удаляет её контейнеры; образы, volumes и сети сохраняются.
- VM и Docker управляются отдельно. Просмотр панели не запускает остановленную VM.

Статистика относится к гостевой Linux VM, а не квоте helios. Неизвестные значения обозначаются «—». Данные обновляются, пока страница видима; автоматическое обновление можно отключить.

## Подключение frontend

Скопируйте адрес маршрута и используйте его как base URL:

```js
const API = '/~USERNAME/helios-container/index.php/vm/8080';
const response = await fetch(`${API}/api/health`);
const result = await response.json();
```

Шлюз сохраняет путь API, query-параметры, тело запроса и `Authorization`. Для frontend на `se.ifmo.ru` CORS не нужен; для другого origin настройте его в backend.

Backend получает `X-Forwarded-Proto`, `X-Forwarded-Host` и `X-Forwarded-Prefix`. Редиректы и пути cookies получают префикс шлюза. HTML и JavaScript не переписываются — абсолютные пути приложения могут потребовать настройки.

## Доступ и ограничения

Приватная ссылка даёт доступ к управлению и логам. Не публикуйте её в frontend или репозитории. **Она не защищает публичный API** — авторизацию должен проверять backend.

Каталоги пользователей на `se.ifmo.ru` разделяют один origin. Не публикуйте Docker API и административные сервисы без собственной защиты.

Шлюз поддерживает:

- HTTP backend по IPv4; для HTTPS-only backend нужен HTTP reverse proxy.
- Методы GET, HEAD, POST, PUT, PATCH, DELETE и OPTIONS.
- Тело запроса до 8 МиБ, ответ до 16 МиБ, таймаут backend 15 секунд. Лимиты хостинга могут быть строже.
- JSON и бинарные тела запросов. `multipart/form-data` не поддерживается.

WebSocket, SSE, потоковые ответы, UDP и произвольные TCP-сервисы недоступны. Для WebSocket нужен отдельный WSS-шлюз или настройка университетского хостинга администраторами.

## Управление

```sh
helios-container web info
helios-container web stop
helios-container web start
helios-container web remove
```

`stop` отключает агент; опубликованный API становится недоступен. `remove` удаляет шлюз, сохраняя frontend, VM, контейнеры и TCP-пробросы.

Повторный `web remove` безопасен, в том числе после удаления каталога шлюза или `web.json`. Команда удаляет только файлы шлюза с его маркерами и служебные настройки; посторонние файлы сохраняются. Если путь содержит ссылку или вместо файла шлюза обнаружены чужие данные, удаление останавливается с ошибкой до изменений.

Шлюз размещается в `~/public_html/helios-container`. Настройки и ключ — в приватном `~/.local/helios-container/web.json`, лог — в `web.log` рядом с ним.

Агент переживает выход из SSH. После перезагрузки helios его можно запустить командой `web start`.
